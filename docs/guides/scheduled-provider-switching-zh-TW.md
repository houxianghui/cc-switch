# 排程切換供應商

> CC Switch 可以依你定義的時間表，為 9 個支援的 CLI 自動輪換目前供應商——例如「週一至週五 09:00–18:00 用公司中轉，其餘時間用個人 Key」。本文說明相關概念、切換的確切行為，以及**排程切換**頁面上的每一個控制項。

## 適合誰用

- 你同時付費了兩個以上供應商，希望各自在合適的時段生效（夜間用便宜的離峰中轉，工作時間用官方端點）。
- 你與團隊共用一台機器或一份額度，希望切換自動發生，不必有人記著去點一下。
- 你想讓 Claude Code 有一個「工作時段」供應商，而 Codex 用另一個預設值——時間表是**依應用**獨立的，每個 CLI 有自己的規則和自己的後備。

如果你每個應用只用一個供應商，那就不需要這個功能——繼續在**供應商**頁面用卡片開關即可。

## 概念

以下四個術語會在介面中反覆出現，值得先讀一遍。

- **排程規則** — 一個 `(應用, 供應商, 時段, 優先順序, 啟用, 備註)` 的綁定，意思是「在這些時段裡，應用 Y 使用供應商 X」。每條規則只屬於一個應用，只指向一個供應商。
- **時段** — 一個 `(星期, 開始, 結束)` 三元組，依**本機本地時間**計算。星期透過「一 ~ 日」標籤選擇，開始與結束為 `HH:MM`。一條規則可以包含多個時段（例如工作日上午*加上*週六下午）。
- **各應用後備** — 當該應用**目前沒有任何規則生效**時要切到的供應商。可留空。設為 `— 無 — （維持目前）` 表示時段之外不動目前供應商。
- **手動佔用（manual pin）** — 如果你手動切換過供應商，排程器會讓位，在目前生效的排程決策被取代之前，都不會覆蓋你的選擇。有規則生效時，這個時刻是目前時段結束；只設了後備時，是你下一次儲存後備。

規則的 JSON 形態（這是實際儲存的結構；你不需要手寫，但看一下有助於理解）：

```json
{
  "app": "claude",
  "provider_id": "a7f3c1e2-...",
  "windows": [{ "dow": [1, 2, 3, 4, 5], "start": "09:00", "end": "18:00" }],
  "priority": 0,
  "enabled": true,
  "note": "公司中轉，辦公時段"
}
```

`dow` 中 `0` = 週日，`6` = 週六。

## 排程器如何運作

- **心跳間隔：60 秒。** 排程器每分鐘喚醒一次，算出此刻每個應用**應該**使用哪個供應商，與目前不一致就切換。此外，應用啟動時會立刻評估一次，因此在時段內啟動 CC Switch 會馬上啟用正確的供應商，不必等最長一分鐘。
- **每個應用的解析順序：** 時段涵蓋「現在」的、已啟用的、優先順序最高的規則勝出。優先順序相同時，最近編輯過的規則勝出。若沒有規則涵蓋「現在」，則使用該應用的後備。若連後備也沒有，就什麼都不做——維持目前供應商。
- **手動優先於目前生效的決策。** 排程器會把你最後一次手動切換的時間，和「目前生效的決策開始生效的時刻」相比較。有規則生效時，該時刻是目前時段的開始；沒有規則生效但設了後備時，取「剛剛結束的那個時段的結束時間」與「你最後一次儲存該後備的時間」中較晚的一個。若你的手動切換較晚，該應用就會被略過。因此在只設後備、沒有規則的設定下，手動切換同樣會被尊重；而且那種情況下佔用不會在時段邊界解除——因為根本沒有時段——它會在你下次變更後備時解除。
- **錯過的心跳不會補跑。** 如果機器睡了三小時，排程器不會補做三小時的切換——它只在下一次心跳評估當下這一刻。
- **每次實際觸發的切換都會記錄。** 系統匣文案是另一套機制：它不是回讀這份記錄，而是依你目前的規則與後備重新計算出來的，而且只在系統匣選單重建時刷新，將滑鼠移上去並不會刷新。

## 開啟排程切換頁面

點擊應用頂列的**日曆時鐘圖示**。你也可以在系統匣圖示上按右鍵選擇**開啟排程**——這會喚起主視窗，若排程切換頁面已經開啟，則重新載入該頁面。

## 如何新增規則

1. 開啟**排程切換**。
2. 點擊**新增規則**。
3. 選擇**應用**。所有支援的 CLI 都在清單裡：Claude Code、Claude Desktop、Codex、Gemini CLI、Grok Build、OpenCode、OpenClaw、Hermes、Pi。
4. 選擇**供應商**。清單只包含該應用已設定的供應商。
5. 設定**時段**。新規則預設給出常用的週一至週五 09:00–18:00。點選星期標籤，然後修改開始/結束。需要第二段時就點**新增時段**。
6. 可選地設定**優先順序**（兩條規則重疊時數值大的勝出）與**備註**（僅供你自己辨識）。
7. 保持**啟用**開啟，點擊儲存。

規則會以卡片形式出現，並顯示易讀的時段摘要（`週一至週五 09:00-18:00`、`每日 22:00-23:59`，更複雜時顯示 `3 個時段`）。

## 如何設定後備

1. 開啟**排程切換**。
2. 在**各應用後備**區塊找到目標應用。
3. 從下拉選單裡選一個供應商——目前時間沒有任何規則涵蓋時，就會切到它。
4. 如果你更希望時段之外不動目前供應商，選 `— 無 — （維持目前）`。

後備會立刻儲存，沒有額外的確認步驟。

## 如何編輯、停用或刪除規則

- **編輯** — 點擊規則卡片上的鉛筆按鈕。供應商、時段、優先順序、備註與啟用狀態都可以改。既有規則的**應用**是固定的；要把時間表搬到別的 CLI，請在那個應用下新增一條，再刪掉這一條。
- **停用但保留** — 撥動規則卡片上的**啟用**開關。被停用的規則完全惰性：既不會觸發，也不會擋住優先順序較低的規則勝出。
- **刪除** — 用卡片上的刪除按鈕。這只刪除規則，供應商本身不受影響。

測試期間通常用停用而非刪除，因為一鍵就能還原。

## 如何依需求立刻執行

想驗證規則是否有效，不必等滿 60 秒。

- **排程切換頁面 → 立即執行。** 會彈出結果提示，例如 `觸發 2，略過 6`——「觸發」表示真的切換了，「略過」表示該應用本來就在正確的供應商上、或被手動佔用、或無事可做。
- **系統匣選單 → 立即執行排程器。** 同一套評估邏輯，無需開啟視窗。

## 執行時你會看到什麼

- **系統匣提示 / 選單文案** — 三者之一：
  - `定時切換：<provider>，至 <time>` — 此刻有規則生效。
  - `定時切換：回退至 <provider>` — 目前無規則涵蓋，後備在管。
  - `定時切換：閒置（無生效規則）` — 無規則涵蓋且沒設後備。
- **頁面上** — 每個有啟用規則的應用都會顯示一行**「下次切換」提示**，說明下一個將要生效的供應商，以及距離現在還有多久；沒有待切換事項的應用不會出現在這裡。如果切換連續失敗（連續 3 次以上，例如某個供應商的設定檔寫不進去），頁面會出現紅色橫幅並顯示失敗次數。每次心跳都會記錄自己的結果，這個次數因此是可靠的。看到橫幅就該去檢查那個供應商本身的設定。

## 刪除帶有規則的供應商

排程規則指向供應商，因此供應商不會在規則不知情的情況下被刪掉。在**供應商**頁刪除供應商時，系統會要求確認；確認之後，供應商本身和所有指向它的排程規則會在同一個 SQLite 交易裡一併刪除（_連帶刪除_），任何一步失敗都不會留下刪了一半的狀態。確認對話框不會告訴你會連帶刪掉幾條規則，但刪除完成後會彈出一則提示，告訴你一共刪掉了多少條排程規則。

如果某條規則確實指向了不存在的供應商，它的卡片會顯示 `供應商已不存在`——用鉛筆按鈕把規則改指到一個仍然存在的供應商，或直接刪除。

## 目前版本的限制

- **不支援跨午夜時段。** 一個時段必須在同一天內開始與結束。`22:00–02:00` 會被拒絕，提示 `v1 不支援跨午夜時段`。請拆成兩個時段：當天 `22:00–23:59`，加上隔天標籤下的 `00:00–02:00`。
- **僅本地時間。** 時段依本機本地時鐘評估。沒有依規則設定時區的能力，也沒有日光節約時間「平移時段」的行為——時制切換後，時段仍是牆上時鐘的 `09:00–18:00`。
- **分鐘粒度、60 秒精度。** 切換可能在時段邊界之後最多晚一分鐘發生。
- **一條規則一個供應商。** 規則內部沒有輪詢或負載分攤；請用多條時段不同的規則實現。
- **手動佔用由新的決策解除，而不是由計時器解除。** 有規則生效時，它會在目前時段結束時解除——如果不想等下一次心跳，邊界過後點一下**立即執行**。
- **只設後備的設定會一直保持佔用，直到你重新儲存後備。** 如果你只設了後備、沒有任何規則，一次手動切換就會壓住後備，直到你再次儲存後備為止：沒有時段邊界可以讓佔用到期，所以也沒有基於時間的解除。這是刻意設計——明確的手動選擇應當優先於一個長期預設值——但確實會讓後備看起來像壞了，直到你在排程切換頁的**各應用後備**裡重新選一次。

## 常見問題與排查

**09:00 到了沒有切換，為什麼？**
最常見的是手動佔用：你在目前時段開始之後（含開始時刻）自己切過供應商，排程器刻意讓位。等時段結束，或結束後點**立即執行**。如果你沒有任何規則、只設了後備，那麼佔用沒有邊界可以到期——重新儲存一次後備即可解除。第二常見的原因是規則的**啟用**開關是關的。

**兩條規則重疊，哪條生效？**
**優先順序**數值較高的那條。優先順序相同時，最近編輯過的那條勝出。給重疊的規則設定不同的優先順序，結果才明確。

**視窗關掉後時間表還跑嗎？**
會跑。CC Switch 會常駐系統匣，心跳迴圈隨之運行。如果你完全結束應用，在再次啟動前不會有任何排程——啟動時會立刻評估一次，追上當下的狀態。

**重新啟動後規則還在嗎？**
在。規則與後備都存在 CC Switch 的資料庫裡，不是記憶體。

**能不能排程切換供應商以外的東西，例如模型或路由設定？**
本版本不行。規則切換的是應用的目前供應商，等同於你手動點一下供應商卡片，因此凡是隨該供應商一起設定的東西（端點、Key、模型對應、路由）都會一起生效。

**兩個應用能共用一條規則嗎？**
不能——每條規則只針對一個應用。請每個應用各建一條。這是刻意設計，為了讓「我改的是哪個 CLI」毫無歧義。

**日誌在哪？**
每次實際觸發的切換都會被記錄。系統匣文案並不是回讀這份記錄——它是在系統匣選單每次重建時，依你目前的規則與後備重新計算的。需要更深入排查時，應用日誌會以 `[schedule]` 前綴記錄心跳失敗。
