# 定时切换供应商

> CC Switch 可以按你定义的时间表，为 9 个受支持的 CLI 自动轮换当前供应商——例如「周一至周五 09:00–18:00 用公司中转，其余时间用个人 Key」。本文介绍相关概念、切换的确切行为，以及**定时切换**页面上的每一个控件。

## 适合谁用

- 你同时付费了两个以上供应商，希望各自在合适的时段生效（夜间用便宜的低峰中转，工作时间用官方端点）。
- 你与团队共用一台机器或一份额度，希望切换自动发生，不用谁去记着点一下。
- 你想让 Claude Code 有一个「工作时段」供应商，而 Codex 用另一个默认值——时间表是**按应用**独立的，每个 CLI 有自己的规则和自己的兜底。

如果你每个应用只用一个供应商，那就不需要这个功能——继续在**供应商**页面用卡片开关即可。

## 概念

以下四个术语会在界面中反复出现，值得先读一遍。

- **调度规则** — 一个 `(应用, 供应商, 时间窗口, 优先级, 启用, 备注)` 的绑定，意思是「在这些时段里，应用 Y 使用供应商 X」。每条规则只属于一个应用，只指向一个供应商。
- **时间窗口** — 一个 `(星期, 开始, 结束)` 三元组，按**本机本地时间**计算。星期通过「一 ~ 日」的标签选择，开始和结束是 `HH:MM`。一条规则可以包含多个窗口（例如工作日上午*加上*周六下午）。
- **各应用兜底** — 当该应用**当前没有任何规则生效**时要切到的供应商。可选。设为 `— 无 — （保持当前）` 表示窗口之外不动当前供应商。
- **手动占用（manual pin）** — 如果你手动切换过供应商，调度器会让位，在当前生效的调度决策被替换之前，都不会覆盖你的选择。有规则生效时，这个时刻是当前窗口结束；只设了兜底时，是你下一次保存兜底。

规则的 JSON 形态（这是实际存储的结构；你不需要手写，但看一下有助于理解）：

```json
{
  "app": "claude",
  "provider_id": "a7f3c1e2-...",
  "windows": [{ "dow": [1, 2, 3, 4, 5], "start": "09:00", "end": "18:00" }],
  "priority": 0,
  "enabled": true,
  "note": "公司中转，办公时段"
}
```

`dow` 中 `0` = 周日，`6` = 周六。

## 调度器如何工作

- **心跳间隔：60 秒。** 调度器每分钟唤醒一次，算出此刻每个应用**应该**使用哪个供应商，与当前不一致就切换。此外，应用启动时会立即评估一次，因此在窗口内启动 CC Switch 会马上激活正确的供应商，不必等最长一分钟。
- **每个应用的解析顺序：** 窗口覆盖「现在」的、已启用的、优先级最高的规则胜出。优先级相同时，最近编辑过的规则胜出。若没有规则覆盖「现在」，则使用该应用的兜底。若连兜底也没有，则什么都不做——保持当前供应商。
- **手动优先于当前生效的决策。** 调度器把你最后一次手动切换的时间，和「当前生效的决策开始生效的时刻」相比较。有规则生效时，该时刻是当前窗口的开始；没有规则生效但设了兜底时，取「刚刚结束的那个窗口的结束时间」与「你最后一次保存该兜底的时间」中较晚的一个。若你的手动切换更晚，该应用就被跳过。因此在只设兜底、没有规则的配置下手动切换同样被尊重；而且那种情况下占用不会在窗口边界解除——因为根本没有窗口——它在你下次修改兜底时解除。
- **错过的心跳不会补跑。** 如果机器睡了三小时，调度器不会补做三小时的切换——它只在下一次心跳评估当下这一刻。
- **每次实际触发的切换都会记录。** 托盘文案是另一套机制：它不是回读这份记录，而是根据你当前的规则与兜底重新计算出来的，并且只在托盘菜单重建时刷新，悬停并不会刷新。

## 打开定时切换页面

点击应用顶栏的**日历时钟图标**。你也可以右键托盘图标选择**打开定时切换**——这会唤起主窗口，如果定时切换页面已经打开，则刷新该页面。

## 如何新建规则

1. 打开**定时切换**。
2. 点击**新建规则**。
3. 选择**应用**。所有受支持的 CLI 都在列表里：Claude Code、Claude Desktop、Codex、Gemini CLI、Grok Build、OpenCode、OpenClaw、Hermes、Pi。
4. 选择**供应商**。列表只包含该应用已配置的供应商。
5. 设置**时间窗口**。新规则默认给出常用的周一至周五 09:00–18:00。点选星期标签，然后修改开始/结束。需要第二段时就点**添加窗口**。
6. 可选地设置**优先级**（两条规则重叠时数值大的胜出）和**备注**（仅供你自己辨识）。
7. 保持**启用**打开，点击保存。

规则会以卡片形式出现，并显示易读的窗口摘要（`周一至周五 09:00-18:00`、`每天 22:00-23:59`，更复杂时显示 `3 个窗口`）。

## 如何设置兜底

1. 打开**定时切换**。
2. 在**各应用兜底**区域找到目标应用。
3. 从下拉框里选一个供应商——当前时间没有任何规则覆盖时，就会切到它。
4. 如果你更希望窗口之外不动当前供应商，选 `— 无 — （保持当前）`。

兜底会立即保存，没有额外的确认步骤。

## 如何编辑、禁用或删除规则

- **编辑** — 点击规则卡片上的铅笔按钮。供应商、时间窗口、优先级、备注和启用状态都可以改。已有规则的**应用**是固定的；要把时间表挪到别的 CLI，请在那个应用下新建一条，再删掉这一条。
- **禁用但保留** — 拨动规则卡片上的**启用**开关。被禁用的规则完全惰性：既不会触发，也不会挡住优先级更低的规则胜出。
- **删除** — 用卡片上的删除按钮。这只删除规则，供应商本身不受影响。

调试期间通常用禁用而不是删除，因为一键就能恢复。

## 如何按需立即执行

想验证规则是否有效，不必等满 60 秒。

- **定时切换页面 → 立即执行。** 会弹出结果提示，例如 `触发 2，跳过 6`——「触发」表示真的切换了，「跳过」表示该应用本来就在正确的供应商上、或被手动占用、或无事可做。
- **托盘菜单 → 立即执行调度器。** 同一套评估逻辑，无需打开窗口。

## 运行时你会看到什么

- **托盘提示 / 菜单文案** — 三者之一：
  - `定时切换：<provider>，至 <time>` — 此刻有规则生效。
  - `定时切换：回退到 <provider>` — 当前无规则覆盖，兜底在管。
  - `定时切换：空闲（无生效规则）` — 无规则覆盖且没设兜底。
- **页面上** — 每个有启用规则的应用都会显示一行**「下次切换」提示**，说明下一个将要生效的供应商，以及距离现在还有多久；没有待切换事项的应用不会出现在这里。如果切换连续失败（连续 3 次及以上，例如某个供应商的配置文件写不进去），页面会出现红色横幅并显示失败次数。每次心跳都会记录自己的结果，这个次数因此是可靠的。看到横幅就该去检查那个供应商本身的设置。

## 删除带有规则的供应商

调度规则指向供应商，因此供应商不能在规则不知情的情况下被删掉。在**供应商**页删除供应商时，系统会要求确认；确认之后，供应商本身和所有指向它的定时规则会在同一个 SQLite 事务里一并删除（_级联删除_），任何一步失败都不会留下删了一半的状态。确认对话框不会告诉你会连带删掉几条规则，但删除完成后会弹出一条提示，告诉你一共删掉了多少条定时规则。

如果某条规则确实指向了不存在的供应商，它的卡片会显示 `供应商已不存在`——用铅笔按钮把规则改指到一个仍然存在的供应商，或直接删除。

## 当前版本的限制

- **不支持跨午夜窗口。** 一个窗口必须在同一天内开始和结束。`22:00–02:00` 会被拒绝，提示 `v1 不支持跨午夜时间窗口`。请拆成两个窗口：当天 `22:00–23:59`，加上次日标签下的 `00:00–02:00`。
- **仅本地时间。** 窗口按本机本地时钟评估。没有按规则设置时区的能力，也没有夏令时「平移窗口」的行为——夏令时切换后，窗口仍是墙上时钟的 `09:00–18:00`。
- **分钟粒度、60 秒精度。** 切换可能在窗口边界之后最多晚一分钟发生。
- **一条规则一个供应商。** 规则内部没有轮询或负载分摊；请用多条窗口不同的规则实现。
- **手动占用由新的决策解除，而不是由计时器解除。** 有规则生效时，它在当前窗口结束时解除——如果不想等下一次心跳，边界过后点一下**立即执行**。
- **只设兜底的配置会一直保持占用，直到你重新保存兜底。** 如果你只设了兜底、没有任何规则，一次手动切换就会压住兜底，直到你再次保存兜底为止：没有窗口边界可以让占用到期，所以也没有基于时间的解除。这是有意设计——明确的手动选择应当优先于一个长期默认值——但确实会让兜底看起来像坏了，直到你在定时切换页的**各应用兜底**里重新选一次。

## 常见问题与排查

**09:00 到了没有切换，为什么？**
最常见的是手动占用：你在当前窗口开始之后（含开始时刻）自己切过供应商，调度器有意让位。等窗口结束，或结束后点**立即执行**。如果你没有任何规则、只设了兜底，那么占用没有边界可以到期——重新保存一次兜底即可解除。第二常见的原因是规则的**启用**开关是关的。

**两条规则重叠，哪条生效？**
**优先级**数值更高的那条。优先级相同时，最近编辑过的那条胜出。给重叠的规则设置不同的优先级，结果才明确。

**窗口关掉后时间表还跑吗？**
跑。CC Switch 会常驻托盘，心跳循环随之运行。如果你完全退出应用，在再次启动前不会有任何调度——启动时会立即评估一次，追上当下的状态。

**重启后规则还在吗？**
在。规则和兜底都存在 CC Switch 的数据库里，不是内存。

**能不能定时切换供应商以外的东西，比如模型或路由设置？**
本版本不行。规则切换的是应用的当前供应商，等价于你手动点一下供应商卡片，因此凡是随该供应商一起配置的东西（端点、Key、模型映射、路由）都会一起生效。

**两个应用能共用一条规则吗？**
不能——每条规则只针对一个应用。请每个应用各建一条。这是有意设计，为了让「我改的是哪个 CLI」毫无歧义。

**日志在哪？**
每次实际触发的切换都会被记录。托盘文案并不是回读这份记录——它是在托盘菜单每次重建时，根据你当前的规则与兜底重新计算的。需要更深入排查时，应用日志会以 `[schedule]` 前缀记录心跳失败。
